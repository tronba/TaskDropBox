# TaskDropBox

TaskDropBox is an accountless assignment hand-in box for an isolated school LAN. It is designed to be prepared before an Internet outage and then run from a standalone Ubuntu Server VM without DNS, cloud services, external assets, or runtime Internet access.

V1 is ready for disposable-VM validation. The implementation specification is in [TaskDropBox_Design_Document.md](TaskDropBox_Design_Document.md).
For continuation after moving the repository or changing development agents, see [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md).

## AI development disclosure

TaskDropBox's initial design and implementation were generated by OpenAI Codex under human direction, requirements, and decision-making. It does not use AI at runtime or send application data to an AI provider. See [AI_DISCLOSURE.md](AI_DISCLOSURE.md) for the complete disclosure and maintainer responsibilities.

## V1 workflow

- A teacher enters a system-wide six-digit creator PIN and creates a task.
- TaskDropBox returns an independent student link and secret teacher administration link.
- A student manually enters a name and submits plain text and/or files.
- An open task accepts work after its due time and marks it late.
- A teacher reviews work, downloads files, exports a safe ZIP, closes/reopens the task, and deletes submissions or the entire task.

There are no teacher or student accounts, profiles, class lists, or cross-task identity records.

## Runtime design

- Ubuntu Server 26.04 LTS
- Python 3.12 or newer
- Django 5.2 LTS
- SQLite and private local file storage
- Gunicorn behind Nginx
- server-rendered HTML and local CSS
- plain HTTP at a static private IP on an isolated LAN

The application itself makes no outbound runtime requests. Plain HTTP is an intentional rapid-deployment tradeoff and does not provide protection from a person capable of intercepting LAN traffic.

The first disposable-VM validation procedure is documented in [docs/first-test.md](docs/first-test.md).

## Repository development

This repository is source-only. Do not treat the development checkout as an installed TaskDropBox server. Production installation, system users, Nginx, systemd, and persistent data belong on the target Ubuntu VM.

When a suitable Python environment is available, the intended checks are:

```text
python -m django check
python manage.py makemigrations --check --dry-run
python manage.py test drops.tests
python -m ruff check .
```

No dependencies need to be installed merely to edit or inspect the source.

## Data locations on the VM

```text
/opt/taskdropbox       application code and virtual environment
/etc/taskdropbox       root-readable configuration
/var/lib/taskdropbox   SQLite database and private uploaded files
```

Back up the SQLite database and files together. Backups can retain student names and submitted work after live deletion and therefore require their own access and expiry policy.
