# TaskDropBox project handoff

## Purpose

TaskDropBox is an offline, account-free assignment submission system for schools during Internet outages, licensed under `AGPL-3.0-or-later`.

The intended deployment is a standalone Ubuntu Server 26.04 LTS virtual machine on a temporary isolated school LAN. Teachers and students use ordinary computers and reach the service through a static private IPv4 address over HTTP. Runtime operation must not require Internet access, DNS, certificates, cloud services, external assets, email, or external authentication.

The initial design and implementation were generated by OpenAI Codex under human direction. See `AI_DISCLOSURE.md`.

## Current status

Version `0.1.0` is implemented and ready for its first disposable-VM test. It has not yet been installed or runtime-tested on the Windows coding machine, because that machine is source-development only. The Ubuntu installer and GitHub Actions workflow are responsible for running the full Django and deployment tests.

At the time of this handoff, the repository files are untracked in Git. Before publishing, review them, create a commit, push to GitHub, and confirm the Actions workflow passes.

The project directory may be moved or renamed. Runtime paths on Ubuntu are fixed by the installer and do not depend on the development checkout location.

## Fixed V1 product decisions

- Product name: **TaskDropBox**.
- License: GNU Affero General Public License v3.0 or later.
- English-only V1, with Django translation-ready UI strings.
- No student or teacher accounts.
- The front page is pupil-focused and opens student tasks; a linked teacher page provides task creation and management.
- Creating tasks requires one system-wide six-digit PIN. Only its password hash is stored.
- Each task receives an independent readable three-word student capability and a high-entropy teacher capability. Only their hashes are stored.
- The one-time creation page is the only normal place where the complete links are displayed; they must be saved or printed.
- Students manually enter their names for each submission.
- V1 supports plain-text answers and uploaded files, but no drafts or rich-text editor.
- Due times are soft: an open task accepts work after the deadline and marks it late.
- Closing a task is the hard submission stop. Teachers can reopen it.
- Teachers can review submissions, download files, export all work as ZIP, delete individual submissions, and delete complete tasks.
- ZIP exports contain a CSV manifest, UTF-8 text files for web answers, and original uploaded content with safe readable names.
- Complete task deletion removes its live database content and files. Backups and previously downloaded exports remain separate operator responsibilities.
- No automatic retention or automatic content deletion.
- Low disk space rejects new writes rather than deleting existing work.
- Desktop and Chromebook use is the priority. QR codes are deferred until V2 or V3.
- V2 may add optional public listing of teacher-selected open tasks, rich text, drafts, and translation files.

Do not silently change these decisions. The authoritative detailed specification is `TaskDropBox_Design_Document.md`.

## Implemented architecture

- Django 5.2 LTS, Python 3.12 or newer.
- SQLite with WAL, busy timeout, foreign keys, and secure deletion enabled where supported.
- Private randomized file storage outside the public static directory.
- Gunicorn bound only to `127.0.0.1:8001`.
- Nginx listens on LAN-facing TCP port 80 and proxies to Gunicorn over loopback.
- Nginx has no access-log recording of capability URLs and uses request/connection limits.
- The Nginx account is deliberately excluded from the `taskdropbox` private-data group.
- Server-rendered templates, local CSS, and minimal local JavaScript; no CDN or browser requests to Internet hosts.
- Argon2 creator-PIN hashing.
- Separate hashed student and administration capabilities.
- Session-scoped creator and per-task teacher authorization.
- Streaming upload size enforcement, aggregate limits, disk-reserve checks, hashes, and path-safe private downloads.
- Generic error pages, correlation IDs, capability-redacted application logging, and restrictive browser security headers.
- A locally downloadable installed-source archive at `/source/` for offline AGPL compliance.

Important source locations:

- `config/` — Django configuration.
- `drops/` — models, forms, authorization, storage, exports, views, management commands, migrations, and tests.
- `templates/` and `static/` — completely local interface assets.
- `deploy/` — systemd, Nginx, and management-wrapper templates.
- `install.sh` and `uninstall.sh` — Ubuntu deployment lifecycle.
- `docs/` — installation, networking, configuration, privacy, backup, upgrade, troubleshooting, and first-test instructions.
- `.github/workflows/tests.yml` — Python/Django matrix tests and an Ubuntu 26.04 installer test.

## Ubuntu installation behavior

Run `sudo bash install.sh` from an extracted release or repository checkout on a fresh Ubuntu Server 26.04 VM.

The installer:

1. verifies Ubuntu 26.04 and root privileges;
2. collects and validates the static IPv4 URL, timezone, creator PIN, size limits, and disk reserve;
3. previews changes before modifying the VM;
4. updates Ubuntu and exits with code 20 if a reboot is required;
5. installs Python, Nginx, SQLite, rsync, and related prerequisites;
6. creates locked service identities and protected paths;
7. copies source to `/opt/taskdropbox` and installs a virtual environment;
8. stores configuration in `/etc/taskdropbox/taskdropbox.env`;
9. stores the database and private files under `/var/lib/taskdropbox`;
10. builds the installed source archive;
11. runs migrations, static collection, Django checks, and all automated tests;
12. checks Nginx configuration and private-file permissions;
13. enables services and performs an HTTP health check.

`--upgrade` preserves data, configuration values, and a pre-upgrade SQLite backup. `--reconfigure` changes supported settings without replacing the installed source. `uninstall.sh` removes services and application code but deliberately preserves configuration and user data.

Pay particular attention to:

- Ubuntu 26.04 package availability and the full installer run;
- creator-PIN login and rate limiting;
- one-time display and saving of student/teacher links;
- text and multi-file submissions;
- on-time versus late boundary behavior;
- close/reopen behavior;
- task-authorization isolation between browsers and tasks;
- authorized downloads and ZIP contents;
- deletion followed by `sudo taskdropbox-manage check_storage --checksums`;
- operation after WAN access is blocked;
- `/source/` availability while offline;
- `--reconfigure`, `--upgrade`, and preserving-data uninstall behavior.

## Safety and privacy boundaries

- Never commit the production environment file, database, uploads, creator PIN, capability links, exports, or backups.
- Do not expose TaskDropBox directly to the public Internet.
- HTTP avoids certificate warnings but is not encrypted; use only on the intended isolated and trusted temporary LAN.
- Do not add telemetry, external fonts/scripts, cloud dependencies, analytics, or online AI calls.
- Student names are self-reported and are not authenticated identities.
- AI-assisted contributors remain responsible for reviewing, understanding, testing, and licensing their changes.
